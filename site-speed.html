02  ·  Diagnosis

What's slowing the page down

We inspected the live PDP in Chrome and read the full Lighthouse report. The phone spends 7.4 seconds of main-thread work on this one page, 4.9 seconds of it running JavaScript. Most of that JavaScript comes from apps and tags, not from Isharya's theme.

Script evaluation 4.4s Parsing and compiling scripts 1.3s Everything else, including layout and paint 1.7s
FINDING 01  ·  CHECKOUT APP LOADED ON THE PRODUCT PAGE
App-side · Track 2

Shiprocket's checkout downloads 1.1 MB before anyone taps Buy

Shiprocket's one-click checkout (served from pickrr.com) loads its full checkout app on every product page visit. The shopper hasn't reached checkout, so almost none of it is used.

HIGHEST IMPACT

2.0 MB of unused JavaScript, and a script that blocks the first paint

Lighthouse finds 2,026 KiB of Pickrr JavaScript unused on this page, the largest single saving in the report. Its marketing script and stylesheet block rendering for up to 1.9 seconds. Shiprocket's tracking script uc.js is also loaded three times, and its iframe alone takes 840ms of main-thread time.

FINDING 02  ·  TRACKING
Theme + app · Track 1 & 2

The Google tag loads five times, alongside four other trackers

Google's tag script (gtag.js) is added four separate times, plus a Google Tag Manager container, adding up to 784 KiB and over 1 second of main-thread time. Lighthouse lists five of the page's 20 long tasks as Google tags.

OVERLAP

Five analytics tools measuring the same visit

Google's tags, the retired Universal Analytics script (analytics.js), Meta Pixel (252 KiB), Microsoft Clarity and Plausible all run on the same page. Most of these can be consolidated into one Tag Manager container and loaded after the page is usable.

FINDING 03  ·  DUPLICATE APPS
App-side · Track 2

Two WhatsApp widgets, and an app that loads itself twice

Two different WhatsApp chat widgets are installed: one from Shiprocket Engage and one from LimeChat. The LimeChat button is a 111 KiB animated GIF. A single chat widget would do the same job.

LEGACY CODE

A sticky add-to-cart app loads jQuery 1.9.1 twice

The add-to-cart app from goldendev.win adds its script twice, and each copy pulls in its own copy of jQuery 1.9.1, a 2013 release. The page also loads Wigzo push and engagement scripts, a Hextom promotion bar, an Instafeed feed, a ReelUp video widget, a SpiceGems country redirect and OTPless login, all on first load.

FINDING 04  ·  THE MAIN PRODUCT PHOTO
Theme-side · Track 1

The product photo is downloaded quickly, then waits 4.4 seconds to appear

Lighthouse's breakdown of the main image shows the server and download take under 0.3 seconds. The remaining 4,420ms is render delay: the photo is ready, but the phone is busy running scripts and waiting on blocking stylesheets, so it can't paint it.

RENDER-BLOCKING

Four stylesheets hold up the first paint

theme.css (1.75s), a Shopify app stylesheet smi-base.min.css (1.65s), the Google Fonts stylesheet (0.75s) and custom.css all block rendering. Critical styles can be inlined and the rest loaded without blocking.

FINDING 05  ·  IMAGES AND CACHING
Theme-side · Track 1

Small icons shipped as large files, and assets that aren't cached

The four trust badges under the buy button (18K Gold Plated, Certified Skin Safe, Easy 7 Day Returns, Free Shipping) are PNGs totalling 155 KiB, almost all of it wasted at the size they're shown. In total, Lighthouse estimates 339 KiB of image savings, and 43 of the page's 49 images have no set width and height.

REPEAT VISITS

668 KiB is re-downloaded on every visit

Meta Pixel, the LimeChat GIF, Shiprocket's scripts and some Shopify checkout files are sent with short or no cache lifetimes, so a returning shopper downloads them again.

03  ·  Our Approach

Fix what's in the theme, then work through the apps

Some of the slowdown sits in Isharya's theme and can be fixed directly. The larger part comes from third-party apps, which need the app vendors involved. We split the work the same way.

PHASE 01

Optimise the theme, then hold the gain

Fix everything inside the theme on a duplicate copy, review it with the Isharya team, ship it, then make sure it doesn't slip back as new changes go live.

→
PHASE 02

Reach the target, then maintain it

Work with app vendors on the scripts dragging the score down until real shoppers pass Core Web Vitals, then hold it there.

TRACK 1 · THEME-SIDE · WHAT WE FIX FIRST
  • Show the product photo first. Mark the main image as high priority and remove what delays its paint.
  • Unblock rendering. Inline critical CSS and load theme, app and font stylesheets without blocking.
  • Defer every non-essential script until the page is usable, or until the shopper interacts.
  • Consolidate tracking into one Tag Manager container and remove the duplicate Google tags and retired Universal Analytics.
  • Right-size images: trust badges as SVG, width and height on every image, modern formats throughout.
TRACK 2 · APP-SIDE · WHAT WE TAKE TO VENDORS
  • Shiprocket / Pickrr: load the checkout only when a shopper taps Buy Now or opens the cart, and load uc.js once.
  • WhatsApp: keep one widget, drop the other, and swap the GIF for a static icon.
  • Sticky add-to-cart: load the script once, or replace it with a lightweight theme feature and drop jQuery.
  • Everything else: review Wigzo, Hextom, Instafeed, ReelUp, SpiceGems and OTPless against their use on the product page.
